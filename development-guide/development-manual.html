1. Architecture Overview #

CityTone is a single-file HTML5 Canvas application with zero external dependencies. It runs entirely in the browser — no build tools, no npm, no frameworks. The architecture follows a modular IIFE pattern:

LaunchPulse.html (806KB)
├── CityTone Player (P)        — main music player + city/galaxy visualizer
├── ToneSync Module            — audio analysis → morph target computation (IIFE)
├── JUNGLE Module              — jungle scene visualizer (IIFE, independent rAF loop)
├── UI Layer                   — playlist, controls, drag-drop
└── Boot/Hash Processing       — scene selection, test hooks
Key Design Principles
  • Single file: Everything in one HTML file for zero-friction deployment
  • IIFE modules: ToneSync and JUNGLE are self-contained IIFEs with clean public APIs
  • Independent rAF loops: JUNGLE runs its own requestAnimationFrame loop, decoupled from the main player
  • Error resilience: Both loops use try-catch with error counting — never kill the rAF chain
  • Pixel art: All visuals use fillRect with image-rendering:pixelated — no sprites, no images
  • Pre-allocated arrays: _freqBands, _riverCols, _ffPos are reused to avoid per-frame GC

3. Core Modules #

CityTone Player (P)

The main player object handles:

  • Audio playback: Web Audio API with AnalyserNode for real-time FFT
  • Frequency analysis: 8 normalized bands (0-1) stored in P._freqBands
  • Scene detection: 180-frame (~3s) evaluation window using triple-score comparison (meditation, nature, energetic) with continuous scoring and spectral flatness via coefficient of variation
  • City rendering: 5 parallax layers, buildings, ships, ferris wheel, weather, seasons, easter eggs
  • Galaxy rendering: 400 stars, 14 solar systems, nebulae, scroll-zoom

4. ToneSync Module #

A self-contained IIFE that reads audio data from the player and computes morph targets for visual elements. Located inside the JUNGLE module scope.

Architecture

ToneSync.create(opts) → {
  metrics: {        // read-only public state
    energy, bassEnergy, midEnergy, highEnergy,
    beatPulse, beatFlag, beatRate,
    riverEnergy, rainEnergy, natureScore,
    flowerBoost, musicActive, isCityPop,
    freqBands[8]
  },
  morphs: {         // computed morph targets (0.7-2.2 range)
    treeH, treeW, mushroomH, mushroomW, templeH
  },
  update(dt, player),   // read audio, compute metrics
  tickTone(dt),         // compute morph targets from metrics
  reset(),              // clear all state
  setForceEnergy(v)     // override energy for testing
}

Adaptive Beat Detection

Algorithm

Tracks a rolling bass baseline (_bassBaseline) that adapts to quiet and loud tracks. A beat fires when bass exceeds both:

  1. Absolute minimum threshold (config.beatThreshold = 0.35)
  2. Adaptive threshold = baseline * beatRatio (catches relative spikes)
_bassBaseline += (bassEnergy - _bassBaseline) * beatBaselineLerp * dt;
var adaptiveThreshold = Math.max(config.beatThreshold, _bassBaseline * config.beatRatio);
if (curBass > adaptiveThreshold && curBass > _prevBass * config.beatRatio && _beatCooldown <= 0) {
  metrics.beatPulse = 1;
  metrics.beatFlag = true;
}

Scene Detection System (v5.3.2 rewrite)

Three independent detectors run every frame, each producing a 0-1 score using continuous (gradual) scoring instead of binary thresholds:

  • _detectMeditationMusic(): Spectral flatness (CV-based) + low energy + low bass ratio + low dynamic range + no beats → Galaxy scene
  • _detectNatureSound(): Spectral flatness + very low bass + high-freq dominance + sustained + no beats → Jungle scene
  • _detectEnergeticMusic() (new v5.3.2): Strong bass + percussive transients + tonal spectrum + good energy → City scene (positive detection, not just fallback)
  • _detectRetroMusic() (new v5.3.4, root-cause fix v5.3.9): Uses three hard gates — mid-frequency dominance (midRatio > 0.43), moderate energy (0.06–0.24), moderate bass (bassRatio < 0.34) — that return 0 for non-retro music. Only music passing ALL gates scores > 0. Detects 80s synth, city pop, retro wave. Retro score competes with energetic score — if retro is higher, jungle is selected. v5.3.9 replaced previous "participation scoring" that gave ALL music 0.4–0.6 regardless of genre
  • Spectral flatness via coefficient of variation (CV = stddev/mean): flatness = 1/(1+cv*2) — high = noise-like (ambient/nature), low = tonal (music)
  • Evaluation window: 180 frames (~3s) at track start, then scene is locked
  • Decision logic: Picks the scene with the highest average score; nature wins over meditation only if clearly dominant (+0.05); retro wins over energetic if retro score is higher

Nature Sound Detection (ToneSync Module)

Uses sustained mid/high frequencies with bass + beat suppression:

  • River energy: sustained mid frequencies with low bass (water flow)
  • Rain energy: sustained high frequencies with low bass (broadband hiss)
  • Lerp rate 0.04 for responsive detection

5. Jungle Scene System #

4-Layer Cache System

The jungle uses a staggered refresh system to balance visual quality with performance:

LayerContentsIdle IntervalMusic IntervalDisco IntervalBuffer
bgSky, stars, sun/moon, clouds, mountains, distant forest6 frames4 frames4 frames_bufs.bg
hillMossy hills, rocks, waterfall cliffs4 frames2 frames2 frames_bufs.hill
midMid-distance forest4 frames1 frame1 frame_bufs.mid
animGround, river, foreground, wildlife, weather FX2 frames1 frame1 frame_bufs.anim
Starvation Prevention: Any layer not refreshed in _STARVE=30 frames gets force-refreshed, bypassing the _maxRefresh cap (3 idle, 4 during music). All four layers (bg, mid, hill, anim) have starvation protection. The _maxRefresh=4 during music ensures all 4 layers can refresh simultaneously when due, eliminating per-cycle stutter.

Tree Sway System (v5.2.2)

Trees visibly bend and sway with music via the _treeSway variable, computed every frame in advance():

// Music-active sway: beat + bass + mid + wind
_swayTarget = beatPulse*0.8 + bassEnergy*0.35 + midEnergy*0.15
            + 0.03*sin(fc*0.015) + 0.02*sin(fc*0.008+1.3)
_treeSway += (_swayTarget - _treeSway) * min(1, 0.12*dt)

// Applied in _trunk() as quadratic height-scaled offset:
_swayDir = (_h1(seed*0.9+0.3) > 0.5) ? 1 : -1  // per-tree direction
_swayOff = _treeSway * h * t * t * _swayDir * 0.12
totalOffset = lean*t*t + curve + twist + _swayOff

// Crown follows via _crownSwayX(seed, h) helper:
_crownSwayX = _treeSway * h * _swayDir * 0.12

Applied to all 8 tree functions: treeEmergent, treePalm, treeTreefern, treeButtress, treeGiant, treeWideLeaf, treeDwarfWide, treeWithered. Crowns, vines, and fronds all offset by _crownSwayX() to follow the trunk bend.

Sky-Only Buffer (v5.2.3)

A dedicated _skyBuf canvas contains only sky elements (gradient, stars, sun/moon, clouds) — no mountains, forests, or terrain. Refreshed alongside the bg buffer whenever bg is stale:

// In render(), after bg refresh:
if(_skyBuf){
  ctx=_skyBuf.ctx; ctx.clearRect(0,0,W,H);
  drawSky(); drawStars(); drawSunMoon(); drawClouds();
  ctx=_ovCtx;  // restore

Exposed via JUNGLE.skyCanvas() for use by P._drawJungleSkyDisk() when L4='jungle' in layer mode. This ensures the jungle sky-disk shows only sky without tropical mountains or ridges overlapping city buildings.

6. Performance Optimization #

Memory Management

TechniqueImplementation
HSL cache (v5.4.0)Map-based cache with 6000-entry cap, partial eviction (25% oldest). Uses Map.keys() iterator — no array allocation. Previous plain-object cache with delete caused V8 dictionary-mode transition (progressive slowdown)
Array reuse_riverCols, _freqBands, _ffPos, _templeTorchSlots, _discoPitfire.gorillaScreen mutated in place with .length=0
Batch decayIdle metrics use grouped Math.pow calls (d1-d5) instead of per-metric
Color quantizationAlpha values rounded to 1/8 increments for fillStyle cache hits
No per-frame closures_drawPanther hoisted to module scope (was inner function in drawPantherChase)
No per-frame Path2DRain + lightning use ctx.beginPath()/ctx.rect()/ctx.fill() instead of new Path2D()

Draw Call Reduction

  • Run batching: drawRiver batches consecutive columns with identical y-values into single fillRect calls (~5x reduction)
  • Culling: Off-screen elements skipped with sx < -W*0.2 || sx > W*1.2
  • Idle optimization: Music-only elements (panther chase, burning trees) skipped when no music; firefly count halved (15 vs 30)
  • Cache once: drawRiver caches skyStops() reflection color once per refresh
v5.4.0 dt Cap Fix: dt is now clamped to [0.25, 5.0] (was [0.25, 3.0]). The previous 3.0 cap caused slow-motion when FPS dropped below 20 — the simulation lost real time. At 5.0, the simulation stays accurate down to 12fps. The death-spiral risk is mitigated by the Map-based hsl cache (eliminates progressive GC pressure) and the staggered layer refresh system (_maxRefresh caps simultaneous refreshes).
v5.4.0 Root Cause of Jungle Slow-Motion: The jungle hsl() cache used a plain JavaScript object with delete for eviction. After ~6000 entries were added/deleted, V8 transitioned the object to "dictionary mode" where property lookups become O(n) hash-table scans. This caused progressive slowdown specific to the jungle (city/galaxy use a separate cache). Fixed by switching to Map which maintains O(1) lookup regardless of add/delete history.

7. Disco Ball Event System #

Trigger Conditions

  • CityPop music detected (P._isCityPop && P._cityPopJungle — requires user opt-in) OR retro music detected (P._isRetro — automatic spectral detection) — combined as _cpOrRetro
  • Night time (nightF > 0.40)
  • Music active
  • v5.3.9: 8% trigger chance every ~50s (3000 frames). The moon normally travels the night sky — disco ball only replaces it for genuine retro/citypop music. All other music = normal moon
  • Active duration: 8-15 seconds (480-900 frames)
  • Post-event cooldown: 50s (3000 frames)
v5.3.9 Hard-Gated Retro Detection — Root Cause Fix: Previous versions (v5.3.4–v5.3.8b) used "participation scoring" in _detectRetroMusic() where every factor contributed points. This meant ALL music scored 0.4–0.6 regardless of genre — no threshold could fix it because the scoring function itself was broken. v5.3.9 replaces participation scoring with three hard gates that return 0 immediately when key retro characteristics are absent:

Gate 1: midRatio < 0.43 → return 0 — mid-frequency dominance is THE key retro indicator. 80s synth/city pop has synth leads in mids (midRatio 0.44–0.55); modern pop/rock/EDM has midRatio 0.30–0.42
Gate 2: energy < 0.06 || energy > 0.24 → return 0 — retro has moderate energy; EDM/rock too loud, ambient too quiet
Gate 3: bassRatio > 0.34 → return 0 — retro synth bass is moderate, not dominant like modern EDM/hip-hop

Only music passing ALL three gates can score > 0. Pop/rock/EDM/ambient = score 0 = _isRetro false = moon travels normally. Thresholds: per-frame > 0.50, retCount > 42/60 (70%), avgRet > 0.50. The CityPop path (_isCityPop) requires user opt-in (_cityPopJungle) and does not auto-trigger.

_audioRainAccum accumulates when rainEnergy > 0.35:

  • 180 frames (3s) → forces rain weather transition
  • 300 frames (5s) → escalates to heavy_rain

Mixer Mode Unified Clock (v5.3.3)

In Mixer mode, all module slots share the same day-night cycle, weather, season, and volumetric lighting. Toggle options (city↔jungle↔universe) only change what's rendered — never the time. Easter eggs in each scape continue using their own spawn timers but read the shared nightF/weather state, so night-only eggs (fireflies, bats, disco ball, lasers) appear/disappear consistently across all scapes.

Sync Architecture
City (P) = Master Clock
  ── updateCelestial()     → time, nightFactor, sunProgress
  ── transitionWeather()   → currentWeather, targetWeather, weatherBlend
  ── transitionSeason()    → currentSeason, targetSeason, seasonBlend
  ├─ JUNGLE.setSync({ time, sunProgress, nightFactor, targetNight,
  │     currentWeather, prevWeather, targetWeather, weatherBlend,
  │     currentSeason, targetSeason, seasonBlend })
  │
JUNGLE (IIFE) = Follower
  ── _syncMode=true  → _tickCelestial/_tickWeather/_tickSeason return early
  ── setSync()        → overwrites internal state + render vars (nightF, curW, etc.)
  ── advance()        → still runs (scroll, easter eggs, FX) but skips clock advance
  ── Easter eggs      → own timers, but read synced nightF for night-only checks
Weather mapping: City weather types not supported by jungle (snow, sleet, hail, dust/sandstorm) are mapped to the closest jungle equivalent via _mapWeatherToJungle() — snow→cloudy, sleet→light_rain, hail→rain, dust→foggy.
  • Sync enable: setAppMode('mixer') calls JUNGLE.setSyncMode(true) — disables _forceDaytime, _lockTime, _forceWeather
  • Sync disable: setAppMode('player') calls JUNGLE.setSyncMode(false) — JUNGLE returns to its own independent clock
  • Per-frame push: City's main loop calls JUNGLE.setSync() every frame in mixer mode, after celestial/weather/season updates
  • Volumetric lighting consistency: JUNGLE's _goldenHour() uses synced _sunProgress; drawStars(), mountain/tree/cloud colors all use synced nightF
  • Easter egg independence: Disco ball uses its own _discoBallTimer countdown; fireflies use per-frame pulse math; both check nightF > threshold for night-only activation
  • Audio-driven weather: JUNGLE's audio rain override (_audioRainAccum) is skipped in sync mode — City handles its own audio weather, which then syncs to JUNGLE
iOS Safari/Edge Audio Compatibility (v5.3.7)

iOS Safari and Edge on iPhone/iPad have strict audio policies that require special handling:

  • Audio element attributes: All 6 audio elements use playsinline + webkit-playsinline (prevents forced fullscreen) and preload="metadata" (iOS blocks preload="auto" to save cellular data)
  • AudioContext resume chaining: _ensureAudio() returns audioCtx.resume() promise when suspended. All .play() call sites chain _ensureAudio().then(el.play()) — iOS rejects .play() if the AudioContext is not running
  • Error feedback: All .catch() handlers show user-facing toast messages ("Playback failed — tap Play again") instead of silent failure
  • File validation: _isAudioFile() validates MIME type + extension before loading — prevents iOS from silently rejecting non-audio files
  • Mixer closure safety: playAllMixer() uses IIFE scope capture for slot index; _layerPlaying[slot] is set inside .then() — prevents false "playing" state if .play() rejects

10. Extending the Project #

Adding a New Animal

  1. Create _initNewAnimal() function that populates an array with position/phase data
  2. Create drawNewAnimal() function using fillRect pixel art
  3. Add the draw call to the anim layer refresh or drawMusicFX() for per-frame
  4. Cull off-screen: if (sx < -P2*20 || sx > W+P2*20) continue;
  5. Clear array on resize in ensureSize()

Adding a New Weather State

  1. Add the weather name to _JWTRANS array with valid transitions
  2. Add it to _IDLE_WEATHERS if it should appear during idle
  3. Add intensity helper function (e.g., function newWI() { ... })
  4. Add drawing logic in the appropriate layer's draw function

Adding a New Music FX Overlay

  1. Create drawNewFX(ctx) function with early-return guard
  2. Use ctx.save() / ctx.restore() for blend modes
  3. Add call in drawMusicFX()
  4. Use pre-allocated arrays for positions — never create per-frame

11. Hard Constraints #

The following constraints must never be violated:

  • No sprites: Jungle scene uses pixel art via fillRect only
  • No green in sun glow: Sun gradient is orange → white → sky blue → purple
  • No fireworks in rain: Rainy weather suppresses fireworks
  • No mammals on river: Jungle river has no swimming mammals
  • Mountains higher than buildings: Background mountains must always be taller
  • _hslCache cap: Must have 6000-entry cap with auto-clear
  • _loop must not stop: Resilient try-catch, always re-schedule rAF
  • _frameBudget BANNED: Time-budget scheduling causes bg layer starvation
  • Scene locked per-track: No mid-song transitions between citytone and universe
  • Max 5 concurrent tracks: Multi-track layer playback supports up to 5 simultaneous audio files (3 default, expandable to 5)
  • Mixer panel on right side (v5.3.0): Layer mixer panel slides in from the right (right:-360px → right:0), with border-left and shadow to the left
  • No mixer button in Player mode (v5.3.0): The topbar mode toggle is the sole portal for switching between Player and Mixer modes
  • Floating mixer button at bottom-right (v5.3.0): right:24px, visible only in Mixer mode when panel is closed
  • Mixer mode shared clock (v5.3.3): In Mixer mode, City is the master clock — all module slots share the same day-night cycle, weather, season, and volumetric lighting. Toggle options only change scapes, not time. JUNGLE's _syncMode must be enabled on mixer entry and disabled on exit
  • Easter eggs independent but synced (v5.3.3): Easter eggs use their own spawn timers but must read the shared nightF/weather state for night-only/weather-dependent activation
  • Retro music detection (v5.3.4, root-cause fix v5.3.9): _detectRetroMusic() uses three hard gates (midRatio > 0.43, energy 0.06–0.24, bassRatio < 0.34) that return 0 for non-retro music. Previous "participation scoring" gave ALL music 0.4–0.6 causing false triggers. When detected, jungle scene is auto-selected and easter eggs activate via the combined _cpOrRetro flag. The moon travels normally for all non-retro music
  • Easter egg retro reactivity (v5.3.4): All easter egg triggers (disco ball, campfire gathering, firefly patterns, bat spotlights) use _cpOrRetro (= _isCityPop || _isRetro) instead of _isCityPop alone, so they activate for both citypop opt-in and retro spectral detection
  • Hybrid mode full width (v5.3.4): In mixer mode hybrid rendering (anim-only layer), the jungle foreground canvas is drawn at full screen width (ctx.drawImage(_bufs.anim.cv,0,0)) — no horizontal scaling. Previous 92% scaling caused the jungle scape to not fill the screen width
  • Visualizer performance optimization (v5.3.4, fixed v5.3.5): _IVL_MUSIC intervals are {bg:4, mid:1, hill:2, anim:1} with _maxRefresh=4 during music (3 idle). v5.3.4 incorrectly slowed these to {bg:6, mid:2, hill:3, anim:1} with _maxRefresh=3, causing slow-motion — v5.3.5 reverts to the correct values. All four layers (bg, mid, hill, anim) have _STARVE=30 starvation protection
  • Scene toggle button (v5.3.5): A City/Jungle scene toggle segment control in the topbar allows manual theme switching in Player mode.
