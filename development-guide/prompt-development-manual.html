1. Introduction #

This manual defines how to write effective AI prompts for developing the CityTone visualizer (LaunchPulse.html). The project is a 748KB single-file HTML5 Canvas application with three auto-detected scenes (City, Universe, Jungle), a full audio player, and a pixel-art rendering engine. Following these patterns will produce correct, performant, constraint-compliant code on the first attempt.

Core principle: Every prompt should answer three questions — what to change, where in the code, and what constraints apply. Vague prompts produce vague code.

2. Providing Project Context #

The AI assistant has access to the project memory and recent conversation topics, but explicit context in your prompt improves accuracy. Always include:

Context ElementWhen to IncludeExample
Scene nameAlways"in the jungle scene" / "in the city scene"
Module nameWhen targeting specific logic"in the ToneSync module" / "in the JUNGLE loop"
Function nameWhen modifying existing code"in the drawHills function" / "in tickTone()"
Layer nameFor jungle rendering"in the foreground layer" / "in the anim layer"
File nameMulti-file changes"in LaunchPulse.html" / "in jungle-dev.html"

Context Template

In the jungle scene of LaunchPulse.html, modify the drawHills function in the hill layer to [SPECIFIC CHANGE]. The jungle scene uses pixel art (fillRect only, no sprites). Maintain the 4-layer cache system with refresh intervals {bg:6, mid:4, hill:6, anim:2}.

3. Hard Constraints in Prompts #

The project has non-negotiable constraints. Include the relevant ones in your prompt to prevent violations. The AI may not know all constraints unless stated.

Visual Constraints
  • No sprites: Jungle uses fillRect pixel art only
  • No green in sun glow: Sun gradient = orange → white → sky blue → purple
  • No fireworks in rain: Rainy weather suppresses fireworks
  • No mammals on river: Jungle river has no swimming mammals
  • Mountains higher than buildings: Background mountains must always be taller
  • Music style indicator hidden: Never display genre labels
Performance Constraints
  • _hslCache cap: Must have 6000-entry cap with auto-clear
  • _loop must not stop: Resilient try-catch, always re-schedule rAF
  • _frameBudget BANNED: No time-budget scheduling (causes starvation)
  • Pre-allocated arrays: _freqBands, _riverCols must be reused, not recreated
  • Layer refresh: _IVL_IDLE = _IVL_MUSIC = {bg:6, mid:4, hill:6, anim:2}, _maxRefresh=3
  • Starvation prevention: _STARVE=30 — force-refresh after 30 frames
Audio Constraints
  • Weather default: Dynamic weather runs without music
  • Rain trigger: rainEnergy > 0.35 sustained 3s → rain, 5s → heavy rain
  • River boost: riverEnergy drives flowBoost = 1 + 0.6*riverEnergy
  • Tree morph: tH *= 1+0.28*bassEnergy, tW *= 1+0.32*bassEnergy, lerp 0.04
  • Day-night cycle: Cosine-eased _targetNight, lerp 0.012/frame (~70s cycle)

Constraint Template

[DESCRIPTION OF CHANGE]. Ensure: (1) pixel art only via fillRect, (2) no green in sun glow, (3) _loop must not stop on error, (4) no _frameBudget scheduling. Test with zero console errors for 10+ seconds.

4. Prompt Templates by Task Type #

4.1 Adding a New Feature

Add [FEATURE NAME] to the [SCENE] scene in LaunchPulse.html. Requirements: - [Requirement 1 — what it does] - [Requirement 2 — visual style / size / position] - [Requirement 3 — audio reactivity if applicable] - [Requirement 4 — which layer it belongs to] Constraints: - Use fillRect pixel art (no sprites) - Scroll with [SPD.layer_name] in the [layer_name] layer - Animate per-frame in drawMusicFX() for smooth motion (no stop-motion) - Guard with early-return if feature is inactive - Pre-allocate arrays, never create per-frame Test: Open in browser, verify zero console errors for 15+ seconds, confirm visual appears correctly.

4.2 Fixing a Bug

Fix the bug where [BUG DESCRIPTION] in [SCENE/FUNCTION]. Symptoms: - [What happens incorrectly] - [When it occurs — e.g., "after 2 minutes", "during heavy rain", "at night"] Expected behavior: - [What should happen instead] Likely cause: - [If known: "the _hslCache grows unbounded" / "flame loop returns early"] Constraints: - Do not break existing [RELATED_FEATURE] - _loop must remain resilient (try-catch, never stop rAF) - Test with [SPECIFIC TEST COMMAND or browser scenario]

4.3 Performance Optimization

Optimize [FUNCTION/LAYER NAME] in the [SCENE] scene for better frame timing. Current bottleneck: - [e.g., "drawHills takes ~200ms per refresh due to path operations"] - [e.g., "too many per-pixel fillRects in drawRockVol"] Optimization approach: - [e.g., "cap element counts: max 7 rocks, 2 trees, 4 bushes per hill"] - [e.g., "widen slotW to reduce total slots"] - [e.g., "batch fillRects by color"] Constraints: - Do NOT use _frameBudget (BANNED — causes bg layer starvation) - Do NOT reduce _maxRefresh below 3 - Do NOT change _IVL intervals (bg:6, mid:4, hill:6, anim:2) - Verify: refresh time should drop from [X]ms to [Y]ms or less - Test with JUNGLE.dbg() to confirm no starvation

4.4 Code Cleanup / Refactoring

Clean up dead code in [MODULE/FILE]. Tasks: - Remove unused variables: [list if known, e.g., "_sustainedMid, _prevBass, _beatCooldown"] - Remove unused functions: [e.g., "fbm2(), pxBandGrad()"] - Consolidate redundant checks: [e.g., "multiple musicActive checks in tickTone()"] - Batch operations: [e.g., "group Math.pow decay calls during idle"] Constraints: - Do not change any visible behavior - Do not remove any function that is called (verify with grep first) - All existing features must still work after cleanup - Test: zero console errors, visual output unchanged

4.5 Visual Enhancement

Enhance [ELEMENT] in the [SCENE] scene. Current state: - [e.g., "trees are static height, no audio reaction"] Desired state: - [e.g., "tree height AND crown size react to bass frequencies"] - [e.g., "tH *= 1+0.28*bassEnergy, tW *= 1+0.32*bassEnergy, lerp rate 0.04"] Visual specs: - Color palette: [e.g., "orange center, white inner, sky blue mid, purple edge"] - Size: [e.g., "PX*9 for sky disks"] - Position: [e.g., "rises/sets behind mountains following sine arc"] - Scroll: [e.g., "SPD.far for background objects"] Constraints: - [Relevant hard constraints from section 3] - Test with music playing and without music

6. Performance Prompt Patterns #

Identifying Bottlenecks

Profile the [LAYER/FUNCTION] and identify performance bottlenecks. Use the debug API: 
JUNGLE.dbg()  // returns timing, counts, state
Known bottleneck: drawHills (~200ms) due to canvas path operations and per-pixel fillRects in drawRockVol. Optimize by: 1. Capping element counts per hill (rocks:7, trees:2, bushes:4) 2. Widening slotW to reduce total hill slots 3. Removing _frameBudget variable (BANNED) 4. Verifying refresh time drops to <60ms Do NOT reduce _maxRefresh or change _IVL intervals.

Memory Optimization

Fix memory growth in [COMPONENT]. Current issue: [e.g., "_hslCache grows unbounded causing crashes after minutes"]. Solution: - Add size cap: [e.g., "6000 entries"] - Auto-clear when cap reached - For arrays: mutate in place instead of creating new objects - Pre-allocate: [e.g., "_freqBands must be pre-allocated and reused"] Test: Run for 5+ minutes, verify no crash and memory stays bounded.

Stop-Motion Prevention

Fix stop-motion animation in [ELEMENT]. Current issue: [e.g., "disco spotlights only update every 6 frames due to layer cache"]. Solution: - Move animation-critical draws to drawMusicFX() for per-frame rendering - Keep static elements in cached layers - Use lerp for smooth transitions between cached states - Ensure all audio-reactive effects update at 60fps Constraints: - drawMusicFX() runs every frame — keep it lightweight - Use early-return guards for inactive features - Pre-allocate position arrays

7. Audio Coupling Prompts #

Adding Audio-Reactive Elements

Make [ELEMENT] react to [AUDIO_METRIC] in the jungle scene. Audio metric: [e.g., "bassEnergy for tree height", "rainEnergy for weather", "riverEnergy for waterfall"] Morph formula: [e.g., "tH *= 1 + 0.28 * bassEnergy"] Lerp rate: [e.g., "0.04/frame for responsive coupling"] Implementation: 1. Read metric from ToneSync.metrics (e.g., m.bassEnergy, m.rainEnergy) 2. Apply morph in tickTone() or draw function 3. Use lerp for smooth transitions: current += (target - current) * rate Constraints: - ToneSync is a self-contained IIFE — do not break its API - Reset state in reset() function - Test with nature sounds (river/rain) AND regular music

Weather Trigger Prompts

Add audio-driven weather: [rainEnergy] triggers [rain weather]. Logic: - Accumulate when rainEnergy > 0.35 (sustained) - 180 frames (3s) → force rain transition - 300 frames (5s) → escalate to heavy_rain - Decay at 0.96/frame when rain stops - Run AFTER _tickWeather to override timer-based selection - Anti-flicker: if current weather IS rain, correct target without restarting blend Variable: _audioRainAccum Test: Play rain sound audio, verify weather transitions within 3-5 seconds.

8. Disco Ball Event Prompts #

Trigger Conditions

Configure the disco ball event trigger. Conditions (ALL must be true): - P._isCityPop && P._cityPopJungle (CityPop music detected) - nightF > 0.40 (night time) - musicActive (music playing) - 60% trigger chance every ~10s (600 frames) - Duration: 15-30 seconds (900-1800 frames) State variable: _discoBall (null when inactive) Init function: _initDiscoPitfire() Draw function: drawDiscoPitfireGathering(ctx) in drawMusicFX()

Animal Gathering

Add [ANIMAL TYPE] to the disco pitfire gathering. Specifications: - Count: [e.g., "2-3 gorillas"] - Size: [e.g., "P2*2.5 (largest)"] - Position: [e.g., "flanking fire, offX = side*P2*(10+i*4)"] - Behavior: [e.g., "sit, bounce with beat, 3 arm poses"] - Scroll: SPD.ground (foreground layer) - Animation: per-frame in drawMusicFX() Pixel art requirements: - Use fillRect only - Silverback silhouette for gorillas - Animated tails for monkeys - Vine-hanging swing for gibbons Test: Trigger disco ball (play CityPop at night), verify animals appear, animate smoothly, and scroll with foreground.

Spotlight System

Add bat/bird spotlights on gorillas during disco ball event. Logic: - When bats/parrots fly over gorilla screen positions - Drop colored cone spotlight (semi-transparent gradient) - Colors: rotate through [magenta, cyan, gold, green, purple, orange] - Beat-synced pulse: intensity *= 1 + 0.5*beatPulse - Spotlight tracks gorilla position (updated per-frame in _discoPitfire.gorillaScreen) Implementation: - Collision check: bat.y < gorilla.y && |bat.x - gorilla.x| < P2*5 - Draw in drawBatGorillaSpotlights(ctx) called from drawMusicFX() - Use ctx.save()/ctx.restore() for blend modes

9. Testing & Verification Prompts #

Standard Test Prompt

Test the changes in [FILE] after composing the code. Test steps: 1. Open [FILE] in browser 2. Open browser console (F12) 3. Navigate to [SCENE] via [URL hash or music] 4. Verify: - Zero console errors for 15+ seconds - [FEATURE] appears and animates correctly - No stop-motion (smooth 60fps) - Scrolling works correctly - Day/night cycle continues - Weather system unaffected 5. Report any errors found If errors occur: - Do NOT suppress with empty catch - Fix the root cause - Re-test until zero errors

Performance Test Prompt

Verify performance after optimization. Test: 1. Open LaunchPulse.html#scene=jungle 2. Let idle animation run for 60 seconds 3. Check JUNGLE.dbg() for: - Frame time < 16ms (60fps target) - [LAYER] refresh time < [TARGET]ms - No layer starvation (all layers refresh within _STARVE=30 frames) 4. Play music with heavy bass 5. Verify disco ball event triggers at night 6. Confirm no memory growth (Chrome DevTools > Memory) Pass criteria: smooth animation, no console errors, no crashes for 5+ minutes.

10. Anti-Patterns to Avoid #

Never do these in prompts or code:

Anti-PatternWhy It FailsCorrect Approach
"Make it look better" No actionable spec — AI guesses Specify exact colors, sizes, positions, motion
"Optimize everything" Too broad — causes regressions Target specific function/layer with measurable goal
Using _frameBudget BANNED — causes bg layer starvation Use fixed _IVL intervals + _maxRefresh cap
Creating arrays per-frame GC pressure, frame drops Pre-allocate and mutate in place
Drawing audio-reactive elements in cached layers only Stop-motion animation (updates every N frames) Draw in drawMusicFX() for per-frame updates
Using sprites or images Violates pixel-art constraint Use fillRect exclusively
Suppressing errors with empty catch Hides bugs, causes silent failures Log error, count it, skip-ahead after 10 errors
Changing _IVL intervals without testing Can cause layer starvation Keep {bg:6, mid:4, hill:6, anim:2} unless explicitly testing
Adding green to sun glow Violates user preference Sun gradient: orange → white → sky blue → purple
"Remove unused code" without grep verification May delete called functions Always verify with grep before removing

11. Pre-Submission Checklist #

Before submitting a prompt for code changes, verify it includes:

  • Scene name specified (jungle / city / universe)
  • Target function or module named
  • Specific change described (not "improve" or "optimize" alone)
  • Visual specs: size (P2/PX units), color (hue or name), position (H/W fractions)
  • Motion specs: scroll speed, animation type, audio reactivity
  • Relevant hard constraints stated explicitly
  • Layer assignment: cached layer (bg/mid/hill/anim) or per-frame (drawMusicFX)
  • Performance constraints: no _frameBudget, pre-allocate arrays, _loop resilience
  • Test instructions: browser scenario, console error check, duration
  • Expected outcome: what should be visible after the change

Quick Reference: Layer Scroll Speeds

SPD.far     = 0.015   // mountains, cliffs, tropical ridges
SPD.midfar  = 0.040   // distant forest
SPD.mid     = 0.090   // mid forest
SPD.hill    = 0.140   // hills with rocks/trees/bushes
SPD.near    = 0.240   // near vegetation
SPD.ground  = 0.400   // foreground (pitfire gathering, ground plants)

Quick Reference: Refresh Intervals

_IVL_IDLE = _IVL_MUSIC = {
  bg:   6,   // sky, sun/moon, clouds, distant mountains
  mid:  4,   // mid forest, waterfalls, river
  hill: 6,   // hills with rocks, trees, bushes
  anim: 2    // animals, fireflies, particles, music FX
}
_maxRefresh = 3      // max layers refreshed per frame
_STARVE    = 30     // force-refresh if layer not updated in 30 frames
